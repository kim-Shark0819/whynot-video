## 배경 (dev 실측, 07:45, ci-04cb9e97)
- 초안 2,937B(상한 2,500, 초과 17%). LLM 줄이기 1번째(52초)로 2,761B가 됐다(초과 10.4%).
- 10.4%는 `SHRINK_TRIM_FIRST = 0.10`보다 조금 크다. 그래서 자르기를 건너뛰고 LLM 줄이기 2번째(62초)를 했다. 결과 2,261B였고, 전체 163초가 걸렸다.
- 보완 6에서 같은 모양의 초안을 자르기로 처리했을 때는 2,733 → 2,500B, 0.002초, 문제 0이었다.
- Fable 줄이기 1번은 50~60초다. 자르기로 끝날 수 있으면 LLM 2번째는 하지 않는 편이 낫다.

## 요구사항 (`app/src/vnew/retake.py`의 `_shrink_draft`만)
1. **1번째 LLM 줄이기(n=1) 전:** 지금 규칙을 유지한다. 초과가 상한 × `SHRINK_TRIM_FIRST` 이하이면 자르기부터 한다.
2. **2번째 이후 LLM 줄이기(n≥2) 전:** 초과 비율과 상관없이 **항상 자르기부터** 해 본다.
   - 상한 안이고 `_shrink_better`를 통과하면 LLM 없이 끝낸다.
   - 못 하면 지금처럼 LLM 줄이기를 한다(2번째 문구의 직전 초과분 안내도 그대로).
3. 같은 글을 두 번 자르지 않는 지금 캐시(`tried`)를 그대로 쓴다. 로그 모양은 그대로다(`shrink_trim ... after=1`).
4. 상수, 도구, 문구, 모델 순서, 출력 한도는 바꾸지 않는다.

## 검사 (rtk-w 이어서, LLM 가짜)
- 초안 +17% → LLM 1번 → 결과 +10.4%(꾸밈 조각이 있는 MOTION/HARMONY 줄) → 자르기로 상한 안. LLM 호출 1, `shrunk=True`, 로그 `after=1`.
- 1번째 줄이기 결과가 보호 조각만 있어 자르기로 상한 안에 못 들면 → LLM 2번째를 한다(호출 2). 2번째 문구에 직전 초과분 숫자가 있다.
- 기존 보완 5·6 검사에서 "2번째 LLM이 불린다"를 기대하는 입력(`kl_y1` 등)이 이제 자르기로 끝나면, 입력을 보호 조각 위주로 바꿔 그 검사 목적(2번째 문구 확인)을 지킨다. 바꾼 곳과 이유를 보고에 적는다.
- 그 밖의 기존 기대값은 바꾸지 않는다.
